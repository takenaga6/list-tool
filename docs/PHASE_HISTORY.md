## Phase 1: 基盤実装（〜2026-03）

### 目的

```
- リストアップツールの基盤構築
- 6つの加点シグナル（S1〜S6）でランクA/B/C/NG判定
- HubSpot連携・自動登録
```

### 実装内容

```
- agents/ 6エージェント
   - rank_agent.py: A/B/C/NG判定
   - keyword_agent.py: 検索クエリ生成
   - search_agent.py: Web検索（Google CSE→DDGS）
   - scraper_agent.py: 企業HP情報抽出
   - hubspot_agent.py: HubSpot登録
   - list_page_agent.py: リストページから企業抽出
- main.py: メインフロー制御
- app.py: Streamlit UI
- config.py: 設定値・キーワードリスト
- docs/: 仕様ドキュメント群
```

### S1〜S6 シグナル定義

```
S1: PR有料媒体掲載（KENJA GLOBAL等）
S2: 健康経営メディア掲載（アクサ生命等）
S3: 法定外福利厚生記載
S4: 健康経営注力
S5: 半年以内のHPリニューアル
S6: 自社ビル保有

ランク基準:
- S1/S2あり時点でB確定
- S1/S2 + S3〜S6が2つ以上 → A
- S1/S2なしの場合、S3〜S6合計3つ以上 → B
```

## Phase 0a C2-v2: 会社名抽出の追加バグ修正（2026-05-12）

### 背景

5/9 走行で Phase 7-B C2 を回避した新たな3パターンが発覚。

### 修正内容

**パターン2対応: 末尾ハイフン除去**（`agents/scraper_agent.py` `_clean_company_name`）

`_dedupe_consecutive` の直後に以下を追加。  
`_NAME_SEP_CHARS` の `[ 　]+-[ 　]+` はハイフン両側にスペースが必要で
末尾 ` -` を処理できなかったため、`$` アンカーで末尾限定除去。

```python
name = re.sub(r"[\s　]*-[\s　]*$", "", name).strip()
```

社名中ハイフン（`A-B商事`）は `$` アンカーにより保護される。

**パターン1対応A: バイパス塞ぎ**（`agents/scraper_agent.py` `extract_company_name_from_media_page`）

旧ロジックは `match.group(1).strip()[:40]` を直接 return しており、
`_clean_company_name`・`_is_valid_company_name` を経由しないバイパスが存在した。

修正後: `_clean_company_name` を経由し、空文字（validation NG）の場合は
次のパターン or 次のタグを試す。元の即 return は空文字を返してしまう問題もあった。

```python
cleaned = _clean_company_name(match.group(1).strip()[:40])
if cleaned:
    return cleaned
```

**パターン1対応C: 文字コード違いカンマ対策**（`utils/company_name_validator.py` ルール1）

HTMLソースが `，`（U+FF0C 全角カンマ）や `,`（U+002C 半角カンマ）を使う場合、
既存の `、`（U+3001）チェックでは素通りする。チェック対象を拡張。

```python
if any(c in name for c in "！？。、，,"):
```

## fix/prime-subsidiary-exception ブランチ記録（2026-05-20）

### 発見した問題

Phase 1 実装時に「大手プライム子会社は NG 除外」という設計意図があったが、実際には
以下の3カ所で例外処理が機能していなかった：

1. `pre_screen()` — 上場キーワード・グループ会社キーワードが先行して NG を返すため、
   プライム子会社が HP 取得前に弾かれていた。
2. `evaluate_rank()` — `emp_n > 200` の汎用チェックがあり、200名超は全員 NG になっていた。
   `check_phase1_must_conditions()` の `is_prime_sub` 例外は事実上デッドコードだった。
3. `PARENT_PRIME_KEYWORDS` が広すぎ — "グループ会社" "100%子会社" 等の generic キーワードを
   含んでいたため、プライム市場以外の子会社が誤って例外通過するリスクがあった。

### 事業背景

本ツールはアウトバウンド（テレアポ・DM）専用のリスト生成ツール。
- 上場企業（本体）は購買窓口到達のハードルが高くアプローチ不可 → NG
- 東証プライム子会社は「親の信用力 × 子会社の意思決定者への近さ」でアプローチ可能 → OK

### 変更内容（3ファイル）

#### `config.py` — `PARENT_PRIME_KEYWORDS` の厳格化

以下の generic キーワードを削除：
- "100%子会社"、"完全子会社"、"グループ会社"、"の連結子会社"、"の関連会社"

これらは「東証プライム上場かどうか」を検証しないため除外。
残したキーワードは「東証プライム上場の」等のプライム市場特定表現と、
確認済みプライム上場親会社名（伊藤忠商事・三井物産・SBIホールディングス等）のみ。

「上場企業の100%子会社」は仮置きとして残す（市場区分不明だが上場確認できる）。

#### `agents/rank_agent.py` — 例外処理の追加

- `pre_screen()`: `_maybe_prime_sub` チェックを追加。True の場合、上場キーワードと
  グループ会社キーワードのチェックをスキップし `evaluate_rank()` に委ねる。
- `evaluate_rank()`: `_is_prime_sub = is_parent_prime_subsidiary(full_text)` を
  `full_text` 計算直後に追加。
  - 上場企業チェック: `and not _is_prime_sub` 条件を追加
  - 従業員数チェック: 汎用 `emp_n > 200` → 範囲別チェックに変更
    - 200-499名（空白帯）: 全員 NG（プライム子会社含む）
    - 500名以上: 非プライム子会社のみ NG

#### `tests/test_phase1_must_conditions.py` — テストケース a〜g 追加

`TestPrimeSubsidiaryException` クラスとして 7 ケースを追加。全 28 テスト通過確認済み。
